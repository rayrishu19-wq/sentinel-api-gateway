## 🤝 Code of Conduct
We expect all contributors to uphold a welcoming, respectful, and professional environment. Please be kind and constructive in all discussions.

---

## 💡 How Can I Contribute?

### Reporting Bugs
If you find a bug, please open an issue using the **Bug Report** template. Provide as much detail as possible, including:
- Steps to reproduce the issue.
- Expected vs. actual behavior.
- Environment information (Node.js, Redis, OS).

### Suggesting Enhancements
If you have an idea for a new feature or improvement, please submit a **Feature Request** template. Describe the feature, why it is needed, and any alternatives you've considered.

### Pull Requests
To submit your changes:
1. Fork the repository and create a new branch from `main`.
2. Implement your changes, ensuring code matches the existing style.
3. Write/run tests locally to verify functionality.
4. Push your branch to GitHub and open a Pull Request.

---

## 🌿 Branch Naming Guidelines
Use descriptive prefix names for your branches:
- `feat/feature-name` (for new features)
- `fix/bug-desc` (for bug fixes)
- `docs/doc-updates` (for documentation changes)
- `refactor/code-improvement` (for code quality updates)

---

## ✅ PR Checklist & Commit Messages
- Ensure each commit message is clean and descriptive (e.g., `feat(cache): add redis cluster support`).
- Keep pull requests focused on a single concern.
- Fill out the PR template completely.
